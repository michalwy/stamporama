# Market Valuation & the Valuation Dialog

What the market paid, as against catalogue value and what the collector paid — and where each shows.

- **Market valuation** (#24/#455/#456; ADR-0022) is the layer above auction tracking: what the market *paid*, as against `valuation.ts`'s catalogue valuation of copies (ADR-0007 §7) — two modules that are never merged, because they answer different questions. The arithmetic is pure, in `src/lib/market-value.ts`: a **datapoint** per `AuctionLotLine` of a `closed` lot carrying a `finalPrice`, at `finalPrice × fxRateToBase` (the rate frozen at `endsAt`, #354) and **excluding** premium and shipping, since those are the seller's terms rather than the stamp's worth. The derived outcome is deliberately not consulted — `won`, `lost` and `observed` are all real prices, and dropping the won ones would discard the results the collector knows best. A single-line lot is `amount ÷ quantity` and needs no catalogue price at all; a **mixed** lot is split pro-rata by each line's *total* catalogue value (unit × quantity) and is skipped **whole** if any line has none, because a partial split hands the missing line's share to its neighbours. A foreign-currency lot with no frozen rate yields nothing — `AuctionLot.fxRateToBase` is null both when no conversion was needed and when none could be had, so the pure input carries an explicit `inBaseCurrency` flag beside the rate. The key is `stamp × condition × certificate × format` — the `StampCatalogPrice` key minus the **edition** axis, since a hammer price belongs to a date and not to a published book — with nulls matched exactly, no fall-back. Aggregation is over **all** datapoints with no minimum sample and no time window (a self-built base cannot afford a threshold that throws away most of what has been recorded), and the headline is the **median**; thin and stale evidence is instead answered by a 0–100 **confidence score** from sample · recency · agreement · purity, bucketed `low`/`medium`/`high`, always shown next to the facts that produced it and never keyed off by any rule. `realizationRatio` is `median ÷ catalogueValue` in base currency, and a key with no datapoints shows **no** market value — nothing is ever synthesized from comparable keys. The server half is `src/lib/market-values.ts` + `GET …/stamps/market-value?stampId=…`: computed **on demand, nothing stored** (ADR-0022 §7 — no table, no queued recompute, no invalidation), one query for the closed lots *mentioning* the asked-about stamps and then **all** of those lots' lines, whose catalogue values come from `valuateItemRows` so the unknown-variant rollup (#238) and format pricing (ADR-0020) are reused rather than re-derived.

- **Price observations are the second source of market value** (#1633; [ADR-0063](../decisions/0063-price-observations.md), amending ADR-0022 §2 and ADR-0029 §2). `PriceObservation` is a realised price from **someone else's** auction — never a lot, sale or purchase, so no auction or purchase read touches the table and nothing has to filter it out. It stores the price **as observed** (`priceBasis` `hammer` | `all_in`, with the premium copied from the house contact when one is picked) and is reduced to the hammer when counted by `observationHammer` (`price-observation.ts`), which is `bidCosting`'s inversion — never a second formula. **Exact or hint is mostly derived**: `observationDoubts` reads `variant` off `isUnknownVariantStamp` and `condition` off a null `conditionId` live, and only `certificateUncertain` is a column, because a null certificate already means *none*. Only an exact one is a datapoint (`extractObservationDatapoints`, whole, `MarketDatapoint.source.kind === "observation"`), so it moves the median, `n`, span and confidence exactly as a lot line does, and joins the ratio ladder in `realization-ratios.ts` (decided with the collector). **The rate is the ECB rate of `soldOn`** (`fetchEcbRateOn` over the ECB data API, `parseEcbHistoricCsv` pure in `ecb-rates.ts`), frozen at the write and re-read only when the day or currency changed or it is still missing — the collection's `ExchangeRate` table is today's snapshot alone and cannot answer a past day. A failed lookup stores null and the observation is a `no-rate` hint until an edit finds one. **Markets are #1634's**, decided with the collector: no market column here, so nothing on the observation can drift from the contact it will be derived from. The Valuation dialog lists them under the Market value grid (`price-observation-sections.tsx`) — counted ones, then *Hints — not counted* with the reason — and is where they are recorded, corrected and deleted; the row menus raise `onMenuOpenChange` so the dialog's `dismissable` drops while one is open (#361). `StampMarketValue.observations` and `EstimatedValueRow.observations` sit beside `lots` rather than in one mixed list: a lot links to our screen, an observation to its address. **A source lot is recorded once** (#1635; ADR-0063 §9): `assertNotRecorded` refuses the same address, or the same lot number in the same auction at the same house (platform when there is none), with `DuplicatePriceObservationError` carrying the existing id — in the domain, so the dialog and the agent API (`agent-api.md`, *Recording price observations*) refuse alike. `listPriceObservations` / `readPriceObservationViews` are the agent API's reads, judged by the same `toView`.

- **Only results from a stamp's anchoring markets count** (#1634; [ADR-0064](../decisions/0064-markets-and-anchoring.md), amending ADR-0022 and ADR-0029). A **market** is a country (ISO 3166-1 alpha-2) on the **contact**, never on a result: `resultMarket` takes an observation's house's, else its platform's, and a lot's sale's seller's, else the sale's platform's — so a market set on a contact re-judges every result already recorded, the ADR-0063 §8 reason for keeping it off the observation. A result whose contacts name none counts as `Collection.homeMarket` (default `PL`, Settings → Collection) — **decided with the collector** over *anchors everywhere* and *always a hint*, since no contact had a market when this landed and either would have moved every existing valuation; the evidence still prints it as *not known*. `CollectionArea.anchorMarkets` inherits as a **whole list** from the nearest area naming any (`resolveAnchoringMarkets`, the #675 price-source shape), falling back to the home market; a stamp is judged by its primary area, else its first — the area `valuateItemRows` reads its catalogue from. `updateCollectionArea` leaves the list alone when it is omitted (unlike its other fields), so `move_area` restating an area cannot clear it. The filter is `partitionByAnchoring` **after** extraction, each datapoint by its **own** stamp, so a mixed lot is still split over all its lines and each share then counts or not; the rest are hints — out of the median, `n`, confidence, `readMarketMedians` totals, estimated value and the ratio ladder (`loadRealizationRatios` builds the same resolver off rows it already loads). `readStampMarketEvidence` is the one read: `StampMarketValue.markets` / `hintMarkets` per key, and `StampMarketEvidence.hints` (lots and observations) plus `anchoringMarkets` per stamp; `readStampMarketValues` is its projection. The Valuation dialog prints the counts in the hover, tags each result's market, lists **Lots from other markets — not counted** under the grid (observations from other markets are hints in the observation list instead, `notCounted: "other-market"`, so they are not listed twice) and names the stamp's anchors in a line under it. Markets are typed as codes; `COMMON_MARKETS` only feeds pickers.

- **Where market value shows** (#457/#458; ADR-0022 §8) is two surfaces and no third: the **Valuation dialog** — the read-only window behind a row's ⋮ → *Show valuation*, renamed from *Catalog prices* because the catalogue is now one of two answers it carries and a window named after one of them hides the other — and the holdings summary bar. Deliberately **not** the stamp *edit* dialog's Prices tab, where the ADR first put it and where this was built before being moved: that tab is where catalogue prices are **typed in**, and a figure that cannot be edited sitting under a grid of inputs reads as one more thing to fill in, while the Valuation dialog is already read-only, already covers a checklist as well as a stamp, and is already reached from every list a stamp appears on. The section **leads** that dialog, above the cross-catalogue average and in the same `CollapsibleSection` box every other section is (extracted to `shared/collapsible-section.tsx` for it), open by default like the average: a section drawing a heading of its own would read as a caption on the page rather than as one more thing to open, and burying it under a dozen collapsed edition tables is how a second answer goes unread. It is rendered at the dialog's top level and fetched on its own, so it answers while the catalogue tables are still loading and is not repeated in each half's no-prices branch. The toolbar toggles stay **pinned above** it even though neither reaches it — they are the window's controls, and a control that scrolls away is one a reader has to go looking for. It is the dialog's **own grid** — conditions × certificates, `MatrixTable` extracted to `shared/price-matrix.tsx` and shared with the catalogue tables, certificate columns unioned across all of them (`marketCertCells`) so one appearing only in an auction result still earns a column everywhere: a median and a list price are read cell against cell, and a reader learns the window once. The cell is a **button** — a grid holds a number but not an argument, so the lots open *under* the table, one key at a time, and the rest (mean, range, n, span, ratio) is the hover. The confidence badge is the **colour of the amount** (`marketConfidenceColor`, the chip's own three), never a chip beside it: a chip made every column ragged, and a column of prices that does not line up cannot be scanned — which is most of what a grid is for. The score is still spelled out in the hover and in `aria-label`, colour alone being nothing a reader can be required to act on; `MarketConfidenceChip` itself stays, for #511's popover and for that hover, both of which have the width for it. The hover is a **panel of labelled lines**, not a sentence — mean, range, sample, span and the catalogue comparison strung together with separators ran into a block that had to be picked apart word by word — and it is the existing `Tooltip` with a new `maxWidth` prop rather than a hover popover of its own: the placement, the viewport clamping and the nesting rules are the hard part and are already right there. The **format is a table, not a column**: it is the axis the catalogue grid has nowhere to put, so each format is its own matrix under its own caption, captioned only when more than one is on screen. Which is also why the market read carries `conditionSortOrder` / `certificateSortOrder` / `formatSortOrder` — the grid is laid out on them, and `-1` for a null certificate or format is the same convention that makes *No cert.* and the single lead everywhere else. Neither toolbar toggle reaches it: a hammer price has no catalogue edition and is aggregated in base currency to begin with. A key with **no** datapoints is absent rather than zero, no-catalogue-prices no longer short-circuits the dialog to an empty state (a single-line lot yields a datapoint with no catalogue price at all, §3), and the no-evidence case is a sentence naming where the figures would come from — an absent section is indistinguishable from one that failed. A **checklist** gets the members' medians summed per cell, and what replaces the per-stamp badge there is **coverage** on the cell's second line (*7 of 40*, amber below full), with no expansion — a set's evidence is every lot of every member: averaging forty confidence scores describes nothing in particular, while a total resting on a fifth of the set is the fact a reader needs. `MarketConfidenceChip` is shared with #511's bid popover rather than drawn twice, two chips being how `medium` stops meaning one thing. The collection total is `aggregateMarketHoldings` beside `aggregateHoldings` in `valuation.ts`, fed by `readMarketMedians` — a *projection* of `readStampMarketValues`, never a second query, so the figure a total is summed from and the figure the dialog prints cannot drift apart. Its **coverage counts are the point**: `valuedCount` / `noEvidenceCount` ride beside it and a copy with no results contributes nothing rather than a catalogue-derived stand-in; copies no longer held are out, exactly as #396 has them. `valuateItemRows` moved to its own `item-valuation.ts` (re-exported from `items.ts`) for one reason: `market-values.ts` values a lot's lines with it and `items.ts` now needs the medians back, and a module below both is what keeps that from being an import cycle.

- A copy valuation says **which** variant it came from (#616): `CopyValuation.sourceStampId` is the descendant the unknown-variant rollup (#238) took its figure from, and null whenever the linked stamp's own price was used. It exists for the listing side — an umbrella has no marketplace item-ID of its own and is listed under its cheapest variant, derived through this field (`listing-catalog-ids.ts`, `offers.md`) — and it is reported *here* rather than re-derived there precisely so a listing and the valuation behind it cannot describe different variants. `pickLowestByBase` is generic over its candidates and returns the candidate **itself** for the same reason: a caller that tagged them reads the tag back off the winner, which is all this needed. Beside it, `CopyValuation.unpricedVariantIds` reports the **coverage** of that rollup (#617): the fully identified variants — the tree's leaves, an intermediate node being an umbrella of its own whose value *is* the lowest of its children (`VariantPrices.identified`) — that carry no price at this key. It changes no figure here: the value stays the lowest of what is priced and is flagged `uncertain`, which is exactly what a catalogue estimate is allowed to be. It exists because a **listing** may not rest on that estimate — it claims to stand under the *cheapest* variant, and with one variant unpriced there is nothing to say which that is, so `listing-catalog-ids.ts` refuses instead of deriving. The asymmetry is the decision: an estimate may be marked as an estimate, a sale may not. `buildDescendantMap` orders each subtree (catalog sort key, nulls last, then name, then id) because **both** of those answers are read off that order: `pickLowestByBase` keeps the *first* candidate on a tie, so an unordered CTE let the variant a copy is valued and listed under change between identical reads, and the unpriced ones are printed in it. CI is what caught it, on the printed list — the tie would have been silent.

- **Estimated value** (#602; ADR-0022 §6 as revised) is the dialog's fourth answer and the only one that is not a measurement: `catalogue × the learned realization ratio` (#520; ADR-0029 §2), per cell, between **Market value** and **What I paid**. It exists because the two screens contradicted each other about the same stamp — the lots screen recommending 35.50 from `catalogue 105.00 × 34%` at the ladder's collection-wide bucket, the dialog answering *"No auction results recorded for this stamp yet"* — and nothing on screen said the two answer different questions. §6's refusal to synthesize an estimate **into the Market value figure** still holds and is why this is a section of its own with no confidence badge; the ADR was **revised in place** rather than quietly contradicted, on the ADR-0029 §8 precedent. **Scope is the dialog and the offer's price table** (#1829 added the second): the holdings summary bar, the collection value and the checklist set totals stay measurement-only, because a ratio resolves for very nearly every cell of every stamp (bucket 4 needs three ratios in the whole collection) and feeding it into a total would turn "what these have fetched" into "catalogue times a constant" while still wearing the measured figure's name. Three rules keep it from reading as measured, and each is a rule about not overstating: a cell with a **measured median is left empty** (an extrapolation printed beside the measurement invites reading the gap between them as a signal, and it is not one); a cell with **no catalogue value is empty**, there being nothing to multiply; and there is **no confidence badge and no confidence colour** — ADR-0022 §5 scores the datapoints *for this key*, of which an estimated cell has none, so borrowing the badge would make the estimate look measured. The **fallback rung still renders**, in the warning tone and labelled *policy, not evidence*, because that is exactly where the collector most needs to know which it is. It is a **grid of its own, never a column of Market value's**, and the reason is the ratio's shape rather than tidiness: the ladder buckets on *condition*, so each **row** resolves its own bucket at its own `n`, and the bucket's name is the whole justification for the figure — `MatrixTable` grew `renderRowAside` (plus `labelWidth`) so the row can state it beside the condition instead of hiding it in a hover, which is the mistake the section exists to correct. The figure is `≈`-prefixed and muted italic — #238's existing vocabulary for *inferred, not recorded* — and clicking it expands the lots the **bucket** was learned from, other stamps' lots by construction. The domain half is `src/lib/estimated-values.ts`: keys enumerated from the catalogue price rows (the stamp's own, plus its descendants' when it is an unknown-variant umbrella — the rollup itself stays `valuateItemRows`'s, so a key from a non-variant descendant simply resolves to nothing and drops out), catalogue values from **`valuateItemRows`, never the dialog's cross-catalogue average**, since that is the ratio's own denominator and the figure the bid recommendation multiplies — reconciling the two screens is the point, so it has to be the same number. The ladder gained `ResolvedRatio.observations` (the deduped list the median was taken over) and `RealizationRatioResolver.describeLots`, deliberately *not* on `RealizationRatio`: only the expanding surface wants lot rows, while `resolve` runs per line for a whole page of lots (#511). A **set** follows Market value's rule — a total with its coverage count and no expansion — and the two counts are complementary, since a member with a measured median at a key is counted there and never here; a row can hold several buckets, so one is named only when the members agree and the count is stated otherwise.

- **On an offer, Estimated value is the suggested price** (#1829, confirmed with the collector on 2026-10-12): the header's price table states minimum, catalogue, Estimated value, market and cost per set, and Estimated value is the row marked as the suggestion and the figure the *New offer* form seeds the price with, where catalogue value did (#230) — one set's, summed for one set of several copies (#2302, `offers.md`). It is a **second read** of the offer's copies (`estimateCopiesByGroup` in `copy-estimates.ts`) rather than a field of `HoldingsSummary`, which stays measurement-only. Two rules differ from the dialog, each deliberately. **A copy with a measured market median is still estimated**: the dialog leaves that cell empty because the estimate is printed beside the measurement, while here market is a row of its own and an estimate that skipped those copies would price the set as though they were worth nothing. **A piece (#2359) is left out**: the ratio is learned from stamps, and a cover's value is not a stamp's. The ratio's source is named only when every copy resolved the same bucket, the set rows' rule; otherwise the count of buckets. The pure half — the per-set average, the source, the margins, which rows exist — is `src/lib/offer-price-table.ts`. **A Facebook group's `catalogPercent` stays a share of the catalogue value**, not of the suggestion (decided with the collector, 2026-10-12): the setting is named for the catalogue, so `OfferFormDialog` takes `catalogValue` beside `priceValue` for it.

- **The catalogue is a bucket of the ratio ladder, and its manual factor the rung beneath it** (#1828; ADR-0029 §2 amended in place). The ladder is area × condition × period → area × condition → area → **catalogue** → **the catalogue's manual factor** → collection → `bidFallbackPercent`. Catalogues overstate by different amounts (Michel ~10×, Fischer 2–5×) and the collection bucket folded them into one median. **The factor sits before the collection bucket, decided with the collector** (comment on #1828): after it, three results from any catalogue would silence every factor. The ratio stays learned — the collector chose a fallback, not a factor that always wins, and that is not to be re-proposed unless he raises it. An observation's catalogue is `CopyValuation.catalogNameId`; the subject's is derived **inside** `loadRealizationRatios` from its area through `buildEffectivePrimaryCatalogMap` — the only book `valuateItemRows` ever values from — so `resolve` still takes area, condition and year and no caller names a book (`LadderSubject`). `CatalogName.manualFactor` is `Decimal(6, 2)`, *catalogue ÷ realised* as collectors say it, applied as its inverse, CHECK > 0; `parseCatalogueFactor` accepts a decimal comma and refuses rather than clamps. Even the empty resolver applies factors, since a collection with nothing recorded is exactly where they matter. `isStatedRatio` marks `catalogue-factor` and `fallback` — the two rungs that are a stated figure — and every surface draws both in the warning tone (*your estimate, not evidence* / *policy, not evidence*); labels are `Michel / Online results` and `Michel / Online — your factor, catalogue ÷ 10`, the catalogue named as the areas screen names a valuing volume. **Settings → Catalogs** shows the learned factor beside the manual one with its `n` (`learnedCatalogueRatio`, deliberately with **no** minimum sample, and `readLearnedCatalogueFactors`), loaded by `getCatalogSettingsTree` only — the other readers of `getCatalogTree` do not pay for a ratio load.
- **Pieces are left out of the ratio** (#2359; ADR-0076 §7): a closed lot with any line, or a price observation, in a format of kind on cover or on piece is not loaded by `loadRealizationRatios` — what a cover fetched says nothing about how far a stamp's catalogue overstates, and a piece's catalogue value is its method's result, not a stamp's. The estimate is not applied to a piece either (`copy-estimates.ts`).

- **The learned ratios are kept for five minutes, and learned again at once after a write they come from** (#2426, settled with the collector on 2026-11-04). `loadRealizationRatios` reads every closed, priced auction lot and every price observation of the collection and values each one, so it costs in proportion to the collection's history — and every offer's screen (its Estimated figure), every Prepare page and every bid anchor asked it. `realization-ratio-cache.ts` keeps one set per collection on `globalThis` (no imports, so its writers cannot form a cycle): shared by every request, a load running shared by those asking meanwhile, a failed one not kept. `forgetRealizationRatios()` is called after each auction-lot write that can change a result or a composition (`auctions.ts`: lot create, edit, not-stamps, transition, delete, every line write, and their agent-API counterparts), each price-observation write, a catalogue's manual factor, the collection's bid percentages and home market, an area's edit (its anchoring markets and catalogue) and a contact's (an auction house's market decides which of its results count, #1634). Anything else the ratios read — a catalogue value or a format factor typed by hand, a sale's premium — reaches them within the five minutes; the collector accepted that lag for an estimate. A new writer of what the ratios are learned from calls `forgetRealizationRatios()` after its write commits, never inside its transaction.

- **What the collector paid** (#560) is the Valuation dialog's third answer and the only one that is a fact about *this collection* rather than about the stamp — market value is what other people paid (#457), the catalogue is what a published book asks. It sits **below Market value and above the catalogue sections**: those tables are the evidence market value is read against so they belong under it, and what was paid is evidence for neither — a different axis, placed beside the other transaction-derived answer. Laid out on the same `condition × certificate × format` grid (`FormatTables` moved to `price-matrix.tsx` for the second reader), sharing the window's unioned certificate columns, so "I paid 40 / the market pays 55 / the catalogue lists 120" reads off one cell position. The arithmetic is pure, in `cost-basis.ts` beside `resolveCostBasis` (`aggregatePurchaseCostsByKey`); `src/lib/purchase-costs.ts` does only what needs a database. **The figures cover the settled copies alone**: a `pending` cost basis (#123 — the copy sits in an open lot, its share of the pool not worked out) and a `none` are **counted on their own line under the figure**, never averaged in at zero and never guessed at, which is why a cell can carry counts and a — instead of a number; that is an answer, and an absent cell would say "none held". Scope is the held, unsold copies of **that stamp exactly** — `copy-counts.ts`'s filter and #348's no-rollup rule, deliberately *not* #238's catalogue rollup from the lowest variant child: a price is a property of the stamp, a copy is a thing on the table. Stamp-only — a checklist's cost is a sum over members, not an average over one key. **Copies from an opening balance are never in it** (#1324): their cost basis is an opening value, not a price paid, so `getStampPurchaseCosts` filters them out by `lot.purchase.kind` rather than counting them as uncosted — see `purchases-and-intake.md`.

- The Valuation dialog is reachable from **every list a stamp appears on** (#114) — the Copies list row's ⋮ was the last that could not open it, its only route being *Edit stamp*, an edit surface where the question was read-only. Ungated there, unlike the stamps and issues rows which still gate on `mainCatalogPrice`: the window answers three questions now, and the two that are not the catalogue stand on their own — a row that *is* a copy always has something for #560 to say. An **auction lot's composition line** reaches it too (#601), from both of the composition's surfaces — the watchlist's *Lot contents* dialog and the sale screen's lot cards — because the question a ceiling is set against is what the stamp has actually fetched, and the line already names the `stamp × condition × certificate × format` the grid is read on. Ungated for the same reason the Copies row is, and it **survives `readOnly`**: the line row's flag suppresses the *editing* entries, on the argument that the edit form is not on screen, which says nothing about a read-only window — the same split the `+ catalog value` slot already makes. In the dialog surface it is portalled to `<body>` beside the two dialogs already there, that panel being transform-centred and so the containing block for a nested `position: fixed`. One dialog per surface remembering which line opened it, not `usePriceDetailsAction` per row — a hook cannot be called in a loop, which is `useChecklistPriceActions`' shape (#531).

- **A piece is valued by its method, from its stamps' prices** (#2359; [ADR-0076](../decisions/0076-piece-valuation-methods.md), superseding #747's recorded value and ADR-0044 §6). A piece is a copy carrying several stamps, or one stamp once on a format whose `StampFormat.pieceKind` is `on_cover` or `on_piece`; `isPiece` in the pure `piece-valuation.ts` says which, and the rules are `valuePiece` there — *Sum of used*, *Michel*, *Fischer*, *Fischer FP/FW/FM*, per the ADR. **Whether a row is a piece is decided inside `valuateItemRows`**, which loads the collection's format kinds once: `ValuationRow.copy` (renamed from `carrier`) is required and non-null for **every** copy — `PIECE_COPY_SELECT` / `pieceCopyOf` in `carrier-value.ts`, spread by `COPY_VALUATION_SELECT` / `copyValuationOf` — carrying the item id, `stampCount`, franking and the copy's own method, scalars only so no caller's `format` or `stamps` select is overridden; every non-copy row passes null, and the compiler lists them. A piece's entries are read in one query, and each stamp on it is valued by the ordinary `valuateAt` **in the condition the method maps to each price's role** (#2375; [ADR-0077](../decisions/0077-valuation-method-roles.md); `valuation-method-roles.ts`, `loadValuationMethods` reads `ValuationMethodRole` with each condition's abbreviation and symbol) and no certificate — its used price at the entry's format and as a single, its cover and on-piece prices at the single — so derivation, editions, the variant rollup and the agreed-book override all apply unchanged; the copy has no condition of its own to steer anything (#2383, ADR-0079 — `ValuationRow.conditionId` is null for a piece copy, and a non-piece row without one is unpriced). The method is `resolveMethod`: the copy's own, else the nearest area up from the **most expensive stamp's** primary area (highest used price as a single, read in the condition the **collection's default** method maps as used — the collector's call, since the method is not known yet) that sets one, else `Collection.valuationMethod` (default `michel`). A price whose role is unmapped is passed to `valuePiece` as `unmapped` and noted there instead of in `missing`; `PieceValuation.unmapped` names method × role and `columns` the condition each price is read from — what the fields are headed by and the arithmetic names (symbol, else abbreviation). **Michel's rule (#2358) is the Michel method's**: where a still-valid stamp's cover EF/MeF/MiF condition has no price (nor mark), `valuateAt` is asked again with `stillValid` (`pickStillValidPrice`, from the used and never-hinged conditions Michel maps, same edition), the price is listed in `PieceComponent.derived` (`~` in the windows), and with either role unmapped the value names it; nothing is written, and no grid or list shows it. `valuatePiece` builds the `CopyValuation`, in the collection currency, with `piece` saying how (method, source, franking, kind, rule, EF/MeF/MiF, `partial`, `missing` stamp × price); a result with nothing priced is unpriced. The modifier and the fault reduction then apply as to any copy. **A format with a kind has no prices of its own**: `getStampFormats(…, { forPrices })` leaves kind formats off the price surfaces, and since #2375 giving a format a kind moves nothing (the reserved rows are gone). A **non-copy row** in such a format — a want, a lot line, a trade line — is valued as a piece of its one stamp: `valuateItemRows` gives it a synthetic `copy` (one draft entry, rate-correct, no own method) before splitting pieces off, the collector's call in #2375. **The recorded value was moved, not dropped**: `convertRecordedPieceValues` (`piece-value-conversion.ts`, once at boot) sets each piece's modifier amount so its modified value equals the recorded one (`convertRecordedValue`, pure), clears `explicitValue`, and keeps and logs a row the method prices nothing on or whose currency has no rate; nothing else reads the column, which a later migration drops. **How the value was reached** (#2353) is carried on the valuation itself, not re-derived: `valuePiece` records each `PieceTerm` (entry, price, unit, percent, times — a missing added price as a term with no unit; a missing price among several compared for the highest only in `missing`), summing each term in whole cents once (`termCents`) so the printed arithmetic adds up, and `PieceValuation` carries the `terms` and the `components` with every price the rule may read. `piece-value-words.ts` turns them into the arithmetic (`pieceArithmetic`: *MiF: 50 % × Mi 123 ⊠ 40.00 PLN + Mi 124 ⊙ 2.00 PLN = 22.00 PLN*) and names the price each stamp shows **on the piece** (`onPiecePrice`: by what is on the cover, ⊠ under Fischer, on piece on a fragment, none without a kind). **Every amount in the arithmetic names its currency** (#2388): the prices are compared in the collection currency (`PieceValuation.currency`), and a price converted from its catalogue's currency is printed as *original = converted* — *Philatelic: 115 % × Mi 7 ⊙ (1.80 EUR = 7.95 PLN) = 9.14 PLN* — the rule applied to the converted figure; a price already in the collection currency is printed once, with its unit, and the total carries the collection currency only. The rate is not printed — the two amounts are enough to read it. The original comes from `PieceComponent.originals` (by price), which `valuateWholePiece` fills from the same read that gave the converted figure, so the two cannot drift; a `~` derived price carries it on both amounts. The price fields above the arithmetic stay in the catalogue's currency, as typed. The Valuation window (`carrier-value-sections.tsx`, one section) lists each stamp's used and on-piece price, then the computed value, the arithmetic, the rule and where the method came from, the franking and the copy's own method — each changeable there (`setCopyFrankingAction` / `setCopyValuationMethodAction`, then `invalidateList`; #2369) — the modifier with its note and the fault reduction, ending in the copy's value; `getCarrierValuation` no longer values the stamps separately (the sum-of-used helpers it used went with it). The identification step draws the same from a preview (`purchases-and-intake.md`). Where it is set: Settings → Formats (kind), Settings → Valuation methods (the collection's method and each method's roles, #2375), an area's **Edit** dialog (#2385, `AreaPieceValuationFields` in `area-form-dialog.tsx`, beside its still-valid mark: *Same as parent* names what it inherits off the parent chosen in the picker, `methodInheritedLabel`; choosing the inherited method stores null, `methodToStore`; the hidden `valuationMethod` reaches `setAreaValuationMethod` from `updateCollectionAreaAction` only when posted), the copy's Edit dialog (franking and own method, only while the copy is a piece), the Valuation window and the identification step (franking and own method, #2369). **The *As inherited* choice names what it inherits** (#2369): `PieceValuation.inherited` is `inheritedMethod` — `resolveMethod` without the copy's own, area name included (`loadValuationMethods` reads area names) — carried whatever the source, so the label (`inheritedMethodLabel`) reads the same while the copy has its own. A piece whose format has no kind is summed at used prices whatever its method, and its rule line says the fix is a format with a kind, not a method.
- **No piece is valued below the sum of its stamps' used prices** (#2397, settled with the collector on 2026-11-03; [ADR-0078](../decisions/0078-piece-used-price-floor.md), amending ADR-0076 §1 and §5). Michel's philatelic rule — at most 15 % above the most expensive ⊙ — is read as the catalogue states it and kept, but six stamps at ⊙ 1.33 come to 1.53 by it and 7.98 soaked off, and a value that makes destroying the cover the better deal is not one the collector uses; the same gap opens under any method (a cheap MiF price, Fischer's 50 %). So `valuePiece` is the rule (`valueByRule`) and then `withUsedFloor`: the **greater** of the rule's figure and *Sum of used* computed exactly as that method computes it — every entry's used price at its own format × quantity, from the mapped used condition — under every method, franking and kind. *Sum of used* (the method, a cover not posted, a format with no kind) is its own floor and gets `floor: null`. `PieceValueResult.floor` / `PieceValuation.floor` carry the sum, the rule's own figure (`ruleAmount`) and `applied`; `terms` stay the **rule's** terms, so the arithmetic still adds up to the rule's figure and `pieceArithmetic` appends the comparison (*· Sum of used 7.98 PLN is higher → 7.98 PLN*, *is lower → 50.00 PLN*, *is the same*, *· Sum of used —* with no used price, *→ 7.98* alone when the rule priced nothing). The floor's terms are not kept: each stamp's used price is listed on its row already. **A missing used price is a missing price under every method** — the floor could have been higher — merged into the rule's `missing` without duplicates, and an unmapped used role into `unmapped`; `piecePricesRead` asks every entry's used price under every rule to match (a later entry of the same stamp shows *as #n*). The row's hover (`pieceValueTitle`) says when the floor was taken, since the rule's words alone would explain a figure it replaced. The modifier and the fault reduction apply to the floored value, unchanged. Michel's *very rare stamps excepted* is not modelled: the modifier covers it by hand. The agent API's `catalogValue.piece.raisedToSumOfUsed` says when the floor is the value.

- **A piece's stamp prices are typed in place, in its Valuation window and in identification** (#2368, settled with the collector on 2026-11-03; the issue's to-be-confirmed decisions taken as written) — a checklist run's shape (#1229, #2161) on the piece's own rows. **Which fields a row has is `piecePricesRead`** (`piece-valuation.ts`, beside `valuePiece` and mirroring it branch by branch), decided by the rule and never by the figures, so a field does not come and go under the typing: a price compared for the highest is asked whether or not it wins, and Fischer's MiF asks every stamp's used price, the top one's included. The columns are the used price and `onPiecePrice`; a price the rule does not read is a dash. **Which row carries a field is `piecePriceSlots`** (`piece-price-entry.ts`, pure): a field is a stamp × price, the first row to read it owns it and a later row shows *as #n*, and an umbrella's row asks the same prices of each identified variant of its tree (the grid's `subtree`, read with the fields) instead of its own. **Every field is the key the value reads**: the condition its column is read from (`PieceValuation.columns`, #2375), single, no certificate, the latest edition of the stamp's main catalogue, written through `quickSetCatalogPrices`. A `TypedPiecePrice` carries that `conditionId`; the client's `usePiecePriceTyping` takes the columns (the Valuation window from its base read, identification from its last preview, held in state adjusted while rendering) and keys the typing on them; a column whose role is unmapped has no field (*not set up*), and a price Michel's rule derived shows as the field's `~` placeholder. The read is `getPiecePriceFields` and the save `setPiecePrices` (`piece-prices.ts`), which parses everything before writing anything. **The value follows the typing without a save** because `valuateItemRows` takes a fourth argument, `TypedCatalogPrices` (the typed prices, each with its condition), put in place of what is on file at the same key before the rule runs (`applyTypedPrices`) — so derivation, the still-valid rule, the variant rollup and the conversion apply to a typed figure exactly as to a saved one; `getCarrierValuation` and `previewPieceValue` pass it on, and the client sends `changedPiecePrices` (only what parses and differs from the file, debounced). A blank field records and deletes nothing. A stamp's own field is amber when the value lists it missing — a price derived by a multiplier is not — and a variant's while it is empty, as in a run; the note counts them. In the window **Save prices** appears once something is typed and closing asks first (`PriceDetailsDialog`); identification saves before the copy is created, blocking on failure as #593's field does. UI: `piece-stamp-prices.tsx` (`usePiecePriceTyping` before the value is read, `usePiecePriceEntry` once it is).

- **A one-stamp piece is shown as any piece** (#2382, following #2359's rule that one stamp once on a format of a kind is valued as a cover): identification lists the stamp with its price fields and the computed value, and drops the loose stamp's *Catalog value* field, which saved a price in the copy's condition that no method reads (`purchases-and-intake.md`). The Valuation window needed nothing: `getCarrierValuation` already answers `multiStamp` from `value.piece`, and every copy carries its `ItemStamp` entry, so a one-stamp cover's window lists its one stamp like any piece's.

- **A copy that is one of several candidate stamps is valued at the cheapest of them** (#1651; [ADR-0065](../decisions/0065-candidate-stamps.md) §5). Each candidate is valued as a copy of it would be — its own area's catalogue, its own issue's format factor, its own variants when it is an umbrella — and `valuateCandidateCopy` takes the lowest in base currency, flagged uncertain, `sourceStampId` naming it. `ValuationRow.candidateStampIds` is required, as `carrier` is, so no reader prices a set at its pointer by omission. Market value is `copyMarketMedian`: the lowest candidate median, and **none while any candidate has no evidence** — the collector's call, since the unevidenced one could be cheaper.

- **A recorded day's value is the Overview's reads at the time, with their gaps and rates kept** (#652; [ADR-0053](../decisions/0053-daily-collection-value-snapshots.md)). `CollectionValueSnapshot` stores, per UTC day, the holdings summary over `excludeGone` — catalogue value, market value and acquisition cost as **three columns never summed**, each beside the counts it left out (unpriced / unconvertible / uncertain; no market evidence; pending / unrecorded cost) and `copiesHeld` — plus active-offer asking value and open auction exposure. The write-off side is not recorded: a gone copy is not part of that day's worth. `CollectionAreaValueSnapshot` holds the same holdings figures per **area subtree** (the Copies screen's area filter; a stamp in two areas counts under both), and no asking or exposure — an offer or lot mixing areas does not split, settled with the collector. All money is in `baseCurrency`, with `rates` (the collection's ECB table restated into the base, read after the figures so a mid-pass refresh is what gets recorded) and `ratesFetchedAt` beside it: **history is never re-converted at today's rate.** A row keeps the meaning the reads had when it was written, even if a scope changes later.

- **A copy's faults lower every value of that copy by a percentage typed on it** (#1560; the track is #1557–#1560). `Item.faultReductionPercent` is a whole percent, 1–100, null for none (CHECK `item_fault_reduction_percent_range`; zero is written as null so *none* has one spelling). It lives on the copy and **never on the fault**: a percentage per fault, multiplied or the largest taken, was considered and rejected with the collector. The arithmetic is `reduceForFaults` / `applyFaultReduction` in `valuation.ts`, applied **once, inside `valuateItemRows`**, to whichever figure the copy has — catalogue or a piece's computed value (#2359; for #747's recorded value the collector chose *every* value over leaving it alone) — and it reaches every reader the way `carrier` does: **`ValuationRow.faultReductionPercent` is required**, a copy reader spreads `copyValuationOf(row)` over a select spreading `COPY_VALUATION_SELECT`, and a row that is not a copy passes `null`. Carrier components pass null too, since the suggestion is the full worth of the stamps the recorded figure is then lowered from. The lowered `CopyValuation` keeps the full figure in `faultReduction` (percent, full amount, full base) and everything else — catalogue, edition, variant, `uncertain`, `explicit` — as it was, those describing where the figure was read. **Market value** is per key, so it is lowered at the per-copy lookups: `aggregateMarketHoldings` takes `{ median, faultReductionPercent }` per copy, and `find_unlisted_copies` lowers its `marketValue` by the same `reduceForFaults`. The stamp's own reads — the Valuation dialog, market medians, estimated values, catalogue prices — are untouched: the reduction is the piece's, not the stamp's. **Totals say so**: `HoldingsTotal` and `MarketHoldingsTotal` carry `faultReducedCount` / `faultReductionBaseAmount`, which the holdings bar, the offer summary bar, the Overview tile, the structure screen, the offer's set figures and listing totals, the suggested price (`suggestedFaultReducedCount` / `suggestedFullPrice`) and the lot builder (`LotCandidate.faultReduction`, `LotPlan.faultReducedItemIds`) turn into a hover naming the figure without the reductions; a single figure carries an amber `−N %` (`FaultReductionMark`) with the full figure in its hover. Because the weights read the same valuation, a purchase lot's split, its percentage of catalogue and a sale's profit split all follow the lowered figure — a reduction set after a lot closed moves the copy's percentage off its lot's, exactly as an edited price does. **A trade's agreed valuation is left at full** (decided with the user, the #747 reasoning): the agreed figure is the partner's book, and a faulty piece is lowered there by the line's manual value; the own valuation reports `ownFaultReductionPercent` on live lines. Daily snapshots record what the reads said that day and are not re-valued (ADR-0053).

- **A copy's catalogue value is adjusted on the copy by a modifier — a percentage, an amount and a note — before the fault reduction** (#2357; the cover valuation track, #2356–#2359). `Item.valueModifierPercent` (whole, ≥ −100, ≠ 0), `valueModifierAmount` (`Decimal(10,2)`, ≠ 0, may be negative) and `valueModifierNote` (only beside one of them) — three CHECKs, zero written as null so *none* has one spelling. **The order was settled with the collector**: figure × (1 + percent / 100) + amount, floored at zero (`modifyValue`), then `applyFaultReduction` — so `faultReduction.fullAmount` is the *modified* figure and `valueModifier.fullAmount` the catalogue's. **The amount has no currency column**: it is in the currency of the figure it adjusts — the catalogue edition the copy is valued from — and `applyValueModifier` adjusts `amount` in that currency and re-converts with the same rates, so *+200 € in Michel* stays the catalogue's statement; a figure with no rate stays unconvertible. It reaches every reader the way the fault reduction does: **`ValuationRow.valueModifier` is required**, `COPY_VALUATION_SELECT` reads the three columns and `copyValuationOf` builds it (`valueModifierOf`), and every non-copy row passes null. **An unpriced copy stays unpriced** — an amount is not a value without the figure it adjusts (the issue's rule). A piece's computed value (#2359) is adjusted like a catalogue figure, its amount in the collection currency the piece is valued in; #2359 moved each recorded value (#747) onto this amount. **What it does not touch**: market value (the evidence is per key; the modifier is a catalogue exception, not what the piece fetched — unlike the fault reduction, which lowers both), the stamp's own reads, and **a trade's agreed valuation** (the amount is stated in the collector's catalogue currency, which the agreed book need not share — #1560's reasoning; a line's manual value answers it). Totals carry no modified count: the issue asks the row and the page to say so, which they do with `ValueModifierMark` (accent tone, so it never reads as the reduction's amber) and the catalogue figure plus note in the hover (`valueModifierHint`). The pure words and input are `value-modifier.ts`; the agent API's `copyValue` carries `valueModifierPercent` / `valueModifierAmount` / `valueModifierNote` / `catalogueAmount` beside the reduction's fields. Grouped duplicate rows agree only when the modifier and its note agree (`sameValuation`).
- **The modifier is set in four places** (#2398, settled with the collector on 2026-11-03; the issue's to-be-confirmed decisions taken as written): the copy's **Edit dialog** and **bulk edit** on Copies (#2357), **identification** — the scan-tile condition step, where the faults are asked (`askFaults`), for a loose stamp and a piece alike — and a **piece's Valuation window** (`CarrierValueSections`), beside the computed value it adjusts. All four are the same three fields, hint and reading: `ValueModifierFields` / `VALUE_MODIFIER_HINT` (`shared/value-modifier-fields.tsx`, the Edit dialog importing the hint) over `parseValueModifierInput`. **In identification it opens empty and is never carried over** (a modifier belongs to one piece, as a fault does); `identifyTilesAction` parses it and `identifyTilesAsNewCopies` asserts it before any copy exists and writes it on **every** copy of a #596 pass (`TileIdentification.valueModifier`). A run of a checklist and *Identify again* do not ask. **What is typed is valued before it is saved**, the #2368 way: `previewPieceValue` takes `valueModifier` and `getCarrierValuation` a fourth argument, the typed modifier in place of the copy's own (absent reads the copy's; the actions read client input through `readValueModifier`, which yields null rather than refusing a preview). The window saves with **Save modifier** (`setCopyValueModifierAction` → `updateItem`) and asks before closing on one unsaved. The result is one line, `ValueModifierResult` — *Computed value 14.00 PLN · +5.00 PLN → 19.00 PLN* — under the fields in identification: a piece's from its preview, a loose stamp's from the step's *Catalog value* field at the single only (a multiple's value is that figure × the format factor, which the field does not hold); the window keeps its own *Modifier …* line in the breakdown. **There is no copy Valuation window for a loose copy** — its ⋮ → *Show valuation* opens the stamp's grids, which describe the stamp and not this copy — so a loose copy's modifier stays in the Edit dialog and identification.
- **The modifier sits under the prices it adjusts, folded to one line unless set** (#2404, settled with the collector on 2026-11-04 — under the prices, hidden by default; the issue's to-be-confirmed decisions taken as written). Most copies never take one, so its fields stood open for nothing, and in identification they came before the prices they adjust. `ValueModifierDisclosure` (`shared/value-modifier-fields.tsx`) is the one line, **▸ Value modifier**, on all three single-copy surfaces: in **identification** under *Variant prices* / the *Catalog value* field for a loose stamp and under the price panel and computed value for a piece (inside the summary box, where that panel is); in the piece's **Valuation window** where it was, under the computed value; in the **Edit dialog** still next to *Faults* / *Value reduction*, which shows no prices to sit under. **A set modifier is never hidden**: the folded line names it (`valueModifierSummary` — *+200 % · Stempel Danzig*), and Edit and Valuation open it on a copy that has one; identification (a new copy) always opens folded. The open state is not remembered between copies. **Folded, the fields stay mounted** (`display: none`), so the Edit dialog's uncontrolled fields still submit — unmounting them would clear a copy's modifier on every save — and an error (a refused save, or what is typed not parsing in the window) holds the line open. The Edit dialog tracks its fields' text in state only for the line; it passes no currency, since it has no catalogue figure to hand. Bulk edit keeps its *Set to…* / *Clear* / *Leave as is* choice, which already folds the fields.
