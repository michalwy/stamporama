# Platform: deployment and the version label

The release image, the Pi's deploy workflow and its runner, other self-hosters' updates, and how the version and release date reach the screen. Split out of [`platform.md`](platform.md) (#2700).

- Self-hosted deployment: CI pushes a multi-arch image to `ghcr.io/michalwy/stamporama` for release tags (`X.Y.Z`, `X.Y`, `latest`) and for every push to `main` whose four suites ran and passed (`main`, `main-<short sha>`; #2712, ADR-0084). `docker-compose.prod.yml` + `.env` for production. `scripts/install.sh` is the curl-able installer. **The owner's instance on the Raspberry Pi is deployed by `.github/workflows/deploy.yml`** (#2689, ADR-0083), **from `main`** (the owner, 2026-11-27, #2712, ADR-0084): `ci.yml`'s last job on a green push to `main`, *Deploy main to the Pi*, dispatches it on `main` with `main-<short sha>` and `automatic=true` — **a merge is a deploy, and a release no longer deploys** — or a manual run with a version (`main-<sha>` or `X.Y.Z`), which is also the rollback, runs `scripts/deploy.sh` on a self-hosted runner on the Pi, in the existing installation directory with its own `.env`: pull by digest, the no-downgrade guard (two `main` builds compare by the image's `org.stamporama.commit-time` label, so a late CI run cannot put an older commit back; a manual run passes `--allow-downgrade`), a pre-deploy `pg_dump`, `docker compose up -d`, the health wait and the rollback to the previous image. Migrations are not rolled back. **That workflow is the only one allowed onto a self-hosted runner** — the repository is public — and `scripts/check-self-hosted-runners.mjs`, run by `tests/unit/self-hosted-runners.test.ts` in the required `Unit tests` check, fails any other workflow that could reach one — **on `main`**: a `pull_request` run uses the pull request's own workflow files, so the check cannot stop such a job from running once. **The Pi's runner refuses it instead**: its job-started hook, `scripts/runner-job-started-hook.sh` (#2697, tested by `tests/unit/runner-job-started-hook.test.ts`), fails every job before its first step unless it is `deploy.yml` from `michalwy/stamporama` at a `v*` tag or `main`, on `release` or `workflow_dispatch`, and fails closed on a missing variable; it is installed outside the repository on the Pi, so a change to it reaches the Pi only when the owner reinstalls it. `tests/unit/deploy-workflow.test.ts` pins the deploy workflow's trigger (`workflow_dispatch` only — never `release`, `push`, `pull_request`, `pull_request_target` or `workflow_call`), runner, environment, concurrency and repository check, and `tests/unit/ci-deploy-main.test.ts` pins `ci.yml`'s dispatching job (a push to `main` only, after `Publish container image`, on a GitHub-hosted runner). **Its log is public**, so the script prints no `.env`, database address, Pi path or application log. The owner's runbook — runner and its hook, `prod` environment, fork approval, turning Watchtower off, rollback, restoring a dump — is [`docs/deployment/pi-deploy.md`](../deployment/pi-deploy.md); **Other self-hosters update with `scripts/update.sh`**, by hand or from their host's cron or a systemd timer (#2690, ADR-0083 § *Other self-hosters*): Watchtower and the `autoupdate` profile are gone, an `.env` that still names the profile keeps starting because no service uses it, and `update.sh` and `install.sh` clear it and remove the installation's leftover Watchtower container, found by its compose labels. Version baked via `STAMPORAMA_VERSION` build arg — `X.Y.Z` for a release, `main-<short sha>` for a `main` build — shown through `getAppVersion()` in `src/lib/version.ts` (`getAppVersionLabel()` puts a `v` only before a release); the **release instant** rides beside it as `STAMPORAMA_BUILD_DATE` (#507), read by `getAppReleaseDate()` and rendered by the shared `AppVersionLabel` on both surfaces that show a version. CI stamps it from the image's own `org.opencontainers.image.created` label so the two cannot disagree. Null is the ordinary case, not a failure — an unstamped build says nothing rather than dating itself, the same call an unset version makes in reading as `dev`. The inline day is the **UTC date sliced off the ISO string** and the localized instant lives only in the hover `Tooltip`: this renders inside a server-rendered shell, and a browser-formatted date in it would disagree with the server's for anyone west of UTC, while a bubble created on hover is never in the server's HTML at all.
