# Colnect List Sync

Keeping a Colnect list in step with this collection: what a list is configured to mirror, how an export is held, and what a difference between the two sides is. The track is #684–#690; the foundation (#684), the import (#685) and the report screen (#686) are built.

- **The loop is export → load → compare → fix, because Colnect gives nothing else** (#684). There is no API and no import — only an **Export list** button producing a CSV, the very file `colnect-list-rules.ts` already reads for trades (#645). So synchronisation cannot be a push and is not attempted as one: an export is loaded here, the two sides are compared, and the collector fixes whichever side is wrong — this one through ordinary screens (#687, #688), Colnect's through the browser extension acting on the page (#689). Nothing in the app ever calls Colnect directly, which is also why the report proposes rather than performs.

- **The join key is `Stamp.colnectId` (#247), and a stamp without one is not comparable.** That is a third state, not a difference: it is neither *on both sides* nor *missing from one*, because nothing was ever asked. A report that counted unlinked stamps as missing on Colnect would say the collection is thousands of items out of step when it is only partly linked, which is a statement about the Assistant's backfill (#250, #280) rather than about the list. Filling those ids in is the Assistant's job and stays there.

- **Scale is the constraint that shapes everything here.** The account read on 2026-08-22 held Collection 5,346 · Swap 3,119 · Sell 3,419 · **Wish 25,145**, plus a dozen custom lists. Any design that assumes a short report is wrong: the snapshot is a table rather than a parsed file kept in memory, the report is a screen with filters rather than a list, and a bulk adopt (#688) exists precisely because twenty-five thousand rows cannot be worked through one at a time.

- **`sourceOfTruth` is a per-list column because Wish disagrees with the other three.** Collection, Swap and Sell are maintained here and published there, so what is here is right and an item only on Colnect is proposed for removal *there*. Wish is the opposite: it is years of clicking *I want this* on Colnect against far fewer `Want` rows, so trusting this side would open with a proposal to delete twenty-five thousand things — formally correct and useless (#688). Two lists in one account genuinely have different answers, which is why this is a column and not a setting.

- **`lt` is a plain integer, not an enum.** Colnect's list ids are visible as `div.ibox_list[data-lt=N]` on every item row — 2 = Collection, 3 = Swap, 4 = Wish, 5 = Sell — and a custom list carries its own number in its `custom_list__N` URL (11, 15, 16 …). Settings offers only the standard four, because Colnect states no *name* for a custom list anywhere a file or a row can be read, so offering one means asking the collector to type it — a screen rather than a constant. The column already holds them, so that screen needs no migration.

- **The settings panel is the condition mapping's shape (#404), not the catalog mapping's (#248)** — every standard list is listed, configured or not, because the set is Colnect's and is fixed; there is nothing to create and nothing to delete. A row appears in the database on the **first touch** of any of its controls, seeded with the built-in defaults plus the change, so ticking *Sync* alone yields a list mirroring what it obviously should. `enabled` off and no row at all are both "not synced" and differ only in whether the setup was kept. One write per control, no draft, no Save.

- **A snapshot is one per mapping and is replaced by the next import** (#685). A history of exports answers a question nothing asks: the report is always about the list *as it stands*, and an old snapshot beside a new one is a second answer to "what is on Colnect" that nothing would choose between. The rows are stored already read — `colnectId` out of the row's `Link`, since the export has no id column — with `quantity` and `conditionAbbrev` taken **for that list** out of the positional per-list columns. `(snapshotId, colnectId)` is indexed and deliberately **not** unique: a hand-edited file may repeat an item, and whether that is an error is the import's judgement, not a constraint failure twenty thousand rows into a bulk insert.

- **"Accepted" hangs off the mapping; "done on Colnect" hangs off the snapshot. The asymmetry is the decision.** `ColnectListDecision` is a standing *ignore this difference*, a judgement about this collection, and a judgement does not expire because a file was read again — so it survives a re-import. "Done" (#686) is a *claim about the state of Colnect*, and a re-import reads that state afresh: a row that comes back is a row that was not actually done, and the report must say so rather than remember a claim that turned out false. A decision's key includes its `kind` — `only-colnect` / `only-local`, and since the report `quantity` / `grade`, which a plain string column let it add without a migration — because the direction can flip between imports — an item removed there for a stamp still `forTrade` here becomes the opposite difference — and one acceptance silently swallowing the other is how a report comes to omit something nobody decided about.

- **The source predicates are a named list, not a filter expression** (`colnect-list-sync-rules.ts`). Four of them: `items_in_collection`, `items_for_trade`, `items_for_sale`, `wants_open`. The copy predicates all mean *in hand* — delivered, not disposed — since a copy already sold is not on offer and a Colnect list still naming it is the discrepancy, not an input to it. Wants are not about copies at all, and anything general enough to express both would be a query language sitting in a settings row. The report evaluates them (#686): `colnectListSourceShape` resolves a stored string to *which flag on `Item`* or *wants*, which is the one thing the query needs about a predicate that Settings does not, and it is pure so the mapping from a string to a column is asserted without a database.

- **The import resolves its own target, because the file names it** (#685). Every row of an export carries the lists that stamp is on, and `colnect-list-rules.ts` counts them and names the likeliest — the one the most rows carry, which in an export of one list is all of them. Matching that name against the configured labels resolves the mapping without a question; the picker is a question only where it matches none, which is what a custom list or one renamed on Colnect looks like. The screen also asks **which list's columns** to read where the file names more than one, and that is a second question rather than the same one: a collector may well load the file's `Test Swap FROM` group into the list they call Swap, and a row's `Quantity` / `Condition` groups are positional, so reading the wrong one stores the wrong count and the wrong grade for every row on two lists.

- **A row with no `Link` is counted, not dropped silently** (#685). The id in that URL is the only join key the two sides share, so such a row cannot become a snapshot row — but it was in the file, and a snapshot quietly holding fewer rows than the export would make every count on the report a lie. Same reasoning as `declaredCount`, which is reported against the rows actually read and never enforced.

- **The report is one SQL query, not a diff in memory** (#686, `colnect-list-report.ts`). Wish is 25,145 rows against a few thousand local ones; loading both sides per scroll page would be megabytes a page. One statement full-outer-joins the two aggregates on `Stamp.colnectId`, buckets each row, applies the filters and returns the page; two more group the same relation for the bucket counts and the country facets. Only the page's own stamps are then hydrated through Prisma. The relation keeps its `in-sync` rows and the callers drop them, so *what a difference is* is spelled once.

- **A row is filed under exactly one bucket, quantity before grade** (#686). A stamp can differ in both, and the row prints both sides' quantity *and* grade either way — but the bucket is the `kind` an *ignore* and a *done* are keyed by, and a row in two buckets would let one acceptance swallow the other, which is the very thing #684 made `kind` part of the key to prevent. Correcting the quantity and re-importing brings the row back under **Grade**, which is correct: it still disagrees.

- **Grade is compared only where the local side agrees on one** (#686). Colnect holds one grade per list entry and this side holds N copies; three copies — two MNH, one used — have no honest single answer, and a precedence rule would quietly under- or over-state the offer. The same sentence reads a want: one naming several acceptable conditions states no grade, and a stamp whose open wants disagree states none either. An unmapped condition (#404) is compared against nothing rather than guessed at. **Quantity and grade *are* compared for a want-backed list** (the collector's call): the local count is the number of open wants, normally one.

- **Country is one string with two sources, and no mapping is invented between them** (#686). Where the row has a local side it is the stamp's primary area name; where it does not, it is the export's own `Country`. The filter lists what the rows actually carry, with counts. Translating Colnect's country names into this collection's area names would be a third mapping table nobody asked for, and a wrong one would silently hide rows from a filter.

- **`ColnectListDoneMark` is a table and not a column, for the asymmetry #684 stated.** It hangs off the **snapshot** and cascades with it, so a re-import clears every claim; `ColnectListDecision` hangs off the mapping and survives. A "done" is a claim about *Colnect's* state that only a fresh export can check — a row that comes back was not done — while an *ignore* is a judgement about this collection that no file can expire. `not-comparable` rows can carry neither, and cannot: both are keyed by a `colnectId` those rows do not have.

- **A list with no snapshot gets the import offered, not a report drawn** (#686). Comparing against an empty Colnect side would announce that the whole collection is missing from the list — formally what the query says, and a lie about what was checked.
